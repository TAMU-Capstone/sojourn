## 1. Purpose and Standing

A **scenario package** is the unit of content in Sojourn. It carries a mission's fiction, its starting conditions, and its win conditions, and it contains **no platform code**. The platform loads it; the platform does not know what is in it.

This document is **normative for the seam** and deliberately silent about everything behind it.

| Normative here — the platform must conform | The team's design — unconstrained |
|---|---|
| Package directory layout and file names | Daemon implementation language and internals |
| `manifest.json` schema | Process model, threading, storage engine |
| Objective and assertion vocabulary (§6) | How assertions are compiled, cached, or indexed |
| Evaluation contract and determinism rules (§7) | Evaluation scheduling beyond the stated contract |
| Command-log format (§8) | Save-file container, compression, on-disk layout |
| Daemon conformance interface (§10) | Every other interface the daemon exposes |
| | The entire ground-station console |

The reason for the split is ownership. The capstone team builds one daemon, once. The sponsor authors scenarios against this format for years afterward, and a later course team maintains the daemon. The format is therefore the long-lived artifact and the daemon is not, so the format is specified and the daemon is not.

> **Charter linkage.** R11.3 requires that all firmware-specific knowledge live in scenario packages. This document is the mechanism: every address, telemetry offset and win condition a scenario needs is expressible here, so platform source has no reason to contain a scenario-specific constant. R13's validation tool checks packages against this document.

## 2. Package Layout

A scenario package is a directory. Its name is not significant; `manifest.json` identifies it.

```
comms-triage/
  manifest.json          required   metadata, link parameters, file references
  briefing.md            required   player-facing mission text, shipped verbatim
  objectives.json        required   the graded objectives and their assertions
  setup.json             optional   probe conditioning applied before play
  firmware/              required   the probe build this scenario was authored against
    probe_rom.elf                   the emulator image
    symbols.json                    generated by the firmware build
    memmap.json                     generated by the firmware build
  docs/                  optional   player-facing documents (recovered manual, etc.)
  assets/                optional   images and other briefing material
  checks/                optional   escape-hatch predicates (§6.7); absent in a pure package
```

A package **shall** be loadable from a directory or from a `.tar.gz` of that directory with the package root at the archive root.

**Pure content.** A package containing no `checks/` directory is a **pure content package**. Charter objective 4 — a new scenario added with zero platform-code changes — is demonstrated with pure packages. §6.7 states when impurity is permitted.

## 3. `manifest.json`

```json
{
  "format": 1,
  "id": "sojourn.comms.triage",
  "title": "Bandwidth",
  "revision": 3,
  "author": "ISA Flight Operations",
  "summary": "The high-gain antenna has failed. Decide what science is worth the downlink.",
  "difficulty": "intermediate",

  "firmware": {
    "rom": "firmware/probe_rom.elf",
    "symbols": "firmware/symbols.json",
    "memmap": "firmware/memmap.json",
    "app_crc32": "0xf72478e0"
  },

  "link": {
    "uplink_delay_s": 8,
    "downlink_delay_s": 8,
    "require_checksum": true,
    "budget": { "writes": 40, "reads": 2000 }
  },

  "briefing": "briefing.md",
  "setup": "setup.json",
  "objectives": "objectives.json",
  "docs": ["docs/MANUAL.pdf"]
}
```

| Field | Required | Meaning |
|---|---|---|
| `format` | yes | Format revision. `1` for this document. A daemon **shall** refuse a `format` it does not implement. |
| `id` | yes | Reverse-DNS-style unique identifier. Save state is keyed on it. |
| `title`, `summary` | yes | Shown in the scenario list. |
| `revision` | yes | Integer, incremented on any content change. See §9 on replay across revisions. |
| `difficulty` | no | Free-form label for the scenario list; carries no mechanical weight. |
| `firmware.app_crc32` | yes | The application image CRC the firmware prints at boot. The daemon **shall** refuse to start a scenario whose probe reports a different CRC, and **shall** say so plainly rather than failing an assertion later. |
| `link.uplink_delay_s` / `downlink_delay_s` | yes | One-way transmission delay the daemon enforces. |
| `link.require_checksum` | no, default `true` | Whether uplinks must carry the CRC-16 suffix. |
| `link.budget.writes` / `.reads` | no | Command allowance (charter R4.2/R4.3: state-changing uplinks and reads are metered separately). Absent means unmetered. |

**Unknown keys.** A daemon **shall** ignore unknown keys at any level rather than rejecting the package. This is what lets format 1 gain optional fields without a flag day. The validator **should** warn about them.

## 4. Firmware Binding

A scenario is bound to one firmware build. `symbols.json` and `memmap.json` are copied from that build's output verbatim.

```json
{
  "format": 1,
  "symbols": { "tlm_priority": "0x20019438", "g_hga_ok": "0x20019433" },
  "fields":  { "g_config": { "tlm_period": 0, "hga_fail_after_s": 140, "...": 0 } }
}
{ "format": 1, "regions": [ { "name": "APP", "lo": "0x20001000", "hi": "0x20019000", "poke": "writable" } ] }
```

Assertions reference **symbols by name**, not raw addresses (§6.3). This is deliberate: a firmware rebuild moves addresses, and a package that named raw addresses would silently begin asserting against the wrong memory. Naming symbols means a rebuild requires copying two JSON files and nothing else.

The `fields` map carries struct member offsets — currently the mission config block — read from the **DWARF of the target build**, not recomputed on the host. Authors therefore write `{"sym": "g_config", "field": "hga_fail_after_s"}` rather than counting bytes through a struct with mixed 8-, 16- and 32-bit members and compiler padding. Hand-computed offsets are the single most likely authoring error in this format, and this removes the opportunity.

> **Instructor note.** `symbols.json` is authoring material and must not reach the player — charter R19 forbids shipping symbol maps in the player image. The package as *authored* contains it; the package as *delivered* is filtered by the build. Keep the authoring copy in the scenario source repository, not in the container.

## 5. Setup: Conditioning the Probe

`setup.json` runs before the player's first frame. It is how a scenario creates the situation it is about — scheduling the antenna failure, degrading a sensor, disabling a capability.

```json
{
  "format": 1,
  "writes": [
    { "at": { "sym": "g_config", "field": "hga_fail_after_s" }, "u32": 300,
      "note": "the dish backs out five minutes in" }
  ],
  "settle_frames": 1
}
```

| Field | Meaning |
|---|---|
| `writes` | Applied in order via the same write path the player uses. Each carries `at` (§6.3) and exactly one of `u8`, `u16`, `u32`, or `hex`. |
| `settle_frames` | Frames to let elapse after setup before evaluation begins. Default `0`. |

Setup writes are **not** charged against the player's budget and **shall not** appear in the command log — they are initial conditions, not moves.

`note` is ignored by the daemon and exists so a package reads as documentation. Authors **should** use it on every setup write; six months later it is the only thing that explains a bare offset.

## 6. Objectives and Assertions

### 6.1 `objectives.json`

```json
{
  "format": 1,
  "objectives": [
    {
      "id": "diagnose",
      "title": "Diagnose the downlink",
      "brief": "Telemetry has thinned. Establish why.",
      "points": 10,
      "success": { "op": "ever", "of": { "op": "commanded", "verb": "PEEK" } },
      "hints": [ { "after_frames": 30, "text": "The COMMS channel reports the antenna in use." } ]
    }
  ]
}
```

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | Unique within the package. Save state and the conformance interface key on it. |
| `title`, `brief` | yes | Player-facing. `brief` is revealed when the objective unlocks. |
| `requires` | no | List of objective `id`s that must be `complete` before this one is evaluated or shown. Cycles are a validation error. |
| `points` | no, default `0` | Weight for scoring. |
| `success` | yes | Predicate (§6.2). When true, the objective becomes `complete`. |
| `fail` | no | Predicate. When true, the objective becomes `failed`. Evaluated before `success`. |
| `partial` | no | List of `{ "when": predicate, "text": "..." }`. The first whose `when` holds supplies diagnostic text — the charter's partial-progress states. |
| `retractable` | no, default `false` | If false, `complete` latches: a later frame cannot un-complete it. |
| `hints` | no | List of `{ "after_frames": N, "text": "..." }`, revealed while the objective is incomplete. |

**Objective states** are `locked`, `active`, `complete`, and `failed`. A daemon **shall** expose exactly these four.

### 6.2 Predicates

A predicate is a JSON object with an `op` key. Predicates are pure functions of the evaluation context (§7) and nest freely.

#### Telemetry

| Predicate | Meaning |
|---|---|
| `{"op":"tlm","path":"channels.COMMS.antenna","cmp":"eq","value":1}` | Compare a decoded telemetry field. `path` is dotted into the decoded frame; a missing path makes the predicate **false**, never an error. |
| `{"op":"channel_present","id":"MAG"}` | The named channel appeared in this frame. |
| `{"op":"channel_absent","id":"MAG"}` | It did not. Distinct from reading zero — a disabled sensor vanishes. |
| `{"op":"event","match":"ANTENNA HGA -> LGA"}` | An event line computed for this frame contains the substring. `"regex": true` switches to a regular expression. |
| `{"op":"tlm_bits","path":"channels.COMMS.xstat","mask":4,"cmp":"eq","value":4}` | Mask a telemetry field and compare. `value` equal to `mask` means "all these bits set"; `0` means "none set". |

`cmp` is one of `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `in`.

#### Memory

| Predicate | Meaning |
|---|---|
| `{"op":"mem_u32","at":{...},"cmp":"gte","value":100}` | Read a little-endian integer and compare. Also `mem_u8` and `mem_u16`. |
| `{"op":"mem","at":{...},"len":10,"cmp":"eq","value":"6043000102030405"}` | Compare a byte range against hex. |
| `{"op":"mem_bits","at":{...},"width":4,"mask":8,"cmp":"eq","value":8}` | Read `width` bytes little-endian, mask, compare. `width` defaults to 4. |
| `{"op":"mem_changed","at":{...},"len":4}` | The range differs from what it held at scenario start — the plain "did they patch this?" test. |

> **Bit tests are not optional sugar.** The probe's control and status registers are bit fields — `XCTRL`, `XSTAT`, `CCTRL`, `CSTAT`, every sensor's `CTRL`. Without `mem_bits` / `tlm_bits` a scenario cannot say "the deployment drive was commanded" without also asserting the value of every other bit in the register, which makes the objective break the moment an unrelated bit changes. Both predicates were added after the reference scenario in §11 turned out to need them — see the note there.

#### Command log

| Predicate | Meaning |
|---|---|
| `{"op":"commanded","verb":"POKE","at":{...},"result":"ACK"}` | A command matching the filter appears in the log. `verb`, `at` and `result` are each optional; omitting all three matches any command. `result` is a prefix match against the probe's reply, so `"ACK"` means *accepted* and `"NAK E04"` means *refused for that reason*. |

> Rejected commands are in the log (§8), so `commanded` without a `result` filter matches a command the probe **refused**. An objective that means "they did this successfully" must say `"result": "ACK"`. This is the most likely way to write an objective that passes when it should not.
| `{"op":"budget","resource":"writes","cmp":"lte","value":40}` | Commands charged so far against an allowance. |

#### Combinators

| Predicate | Meaning |
|---|---|
| `{"op":"all","of":[ ... ]}` | Every child holds this frame. |
| `{"op":"any","of":[ ... ]}` | At least one holds. |
| `{"op":"not","of": { ... }}` | The child does not hold. |
| `{"op":"ever","of": { ... }}` | The child has held in **some** frame so far. Latching. |
| `{"op":"sustained","frames":3,"of": { ... }}` | The child has held in the last N consecutive frames — the antidote to a one-frame flicker counting as success. |
| `{"op":"within","frames":20,"of": { ... }}` | The child held at least once in the last N frames. |

`all` with an empty `of` is **true**; `any` with an empty `of` is **false**. Stating this prevents two implementations from disagreeing on a degenerate package.

### 6.3 Address References

Every predicate that touches memory takes an `at` object:

```json
{ "sym": "g_config", "field": "hga_fail_after_s" }   // preferred where a field exists
{ "sym": "tlm_priority", "offset": 3 }               // preferred otherwise
{ "addr": "0x2001E204" }                             // permitted, for peripheral registers
```

The three forms resolve as follows. `sym` alone is the symbol's address. `sym` + `field` adds the offset from the `fields` map (§4) and is an error if the symbol has no such field. `sym` + `offset` adds a literal byte offset. `addr` is an absolute address — legitimate for the peripheral register blocks, which have fixed addresses by specification and no symbols, and discouraged everywhere else.

A daemon **shall** resolve `sym` through the package's `symbols.json` and **shall** fail validation, not evaluation, on an unknown symbol or field. A resolved address outside every region in `memmap.json` is a **validation error** — this is the third seeded-defect class in charter R13.

### 6.4 Comparison Semantics

Comparisons are exact. Integers do not compare against strings; a package that writes `"value": "1"` where an integer is meant is a validation error rather than a silent mismatch. `in` takes an array. Byte comparisons are case-insensitive hex without separators.

### 6.5 Why This Vocabulary

The set above is not arbitrary. It is the closure of what the reference scenarios need, and each entry earns its place by covering one of the four patch styles the firmware supports (spec §6.5):

| Patch style | The predicate that verifies it |
|---|---|
| Data patch — change a value | `mem_u32`, `mem` |
| Configuration patch — change behavior via the config block | `mem_u32` plus a `tlm` predicate showing the behavior changed |
| Code patch — alter a branch | `mem_changed` over the function's entry pad, plus telemetry proving the new behavior |
| Code injection — a detour into the cave | `mem_changed` over the cave slot, plus `sustained` telemetry proving the hook runs every cycle, not once |

The last row is the one that justifies `sustained`. A `CALL` runs a routine once; a task hook runs it forever. Only a predicate that spans frames can tell those apart, and telling them apart is the whole difficulty ladder of the platform.

### 6.6 Determinism

Predicates **shall** be pure functions of the evaluation context. A predicate **shall not** consult wall-clock time, a random source, the host filesystem, or network. This is not stylistic: charter R15.1 restores progress by replaying the command log against a fresh probe, and a predicate that read the clock would make a replayed log reach a different verdict than the original session.

### 6.7 The Escape Hatch

An objective may name an external predicate:

```json
{ "op": "script", "lang": "python", "entry": "checks/triage.py:pointing_recovered" }
```

The named callable receives the evaluation context and returns a boolean. The rules around it are strict, because it is the one place the pure-content invariant can leak:

1. A package containing `checks/` **shall** declare `"impure": true` in its manifest. The validator **shall** report it prominently.
2. The daemon **shall** support a **pure mode** that refuses to load impure packages, and pure mode **shall** be the default for any packaged distribution.
3. Scripts **shall** obey §6.6 determinism and receive no capabilities beyond the context object.
4. The reference scenarios (§11) are pure. If an escape hatch becomes necessary to express an ordinary objective, that is evidence the vocabulary is missing an entry — **extend §6.2 rather than reaching for the hatch.**

The hatch exists so that one awkward objective in 2028 does not require a format revision. It is not an authoring convenience.

## 7. The Evaluation Contract

This is what a daemon must actually guarantee, and the part most likely to be got subtly wrong.

**When.** Objectives are evaluated **once per received downlink frame**, after the frame is decoded and its event list computed, and after any commands whose downlink delay has expired have been logged.

**In what order.** Objectives are evaluated in declaration order. Within an objective: `fail`, then `partial`, then `success`.

**Against what.** The evaluation context is:

| Name | Contents |
|---|---|
| `frame` | The decoded telemetry frame, in the shape `tlm_decode.py --json` emits. That tool is normative for the decode (firmware spec §9). |
| `events` | Event strings computed for this frame against the previous one. |
| `history` | Previously decoded frames, oldest first, for `sustained` / `within` / `ever`. |
| `mem` | A read handle, `(address, length) -> bytes`. |
| `baseline` | Memory contents captured after setup and before the first player command, for `mem_changed`. |
| `log` | The command log so far (§8). |
| `budget` | Commands charged per resource. |

**Memory snapshot semantics.** All `mem` reads within one evaluation pass **shall** observe the probe as of that frame boundary. An implementation that reads live memory mid-pass can see a value change between two predicates of the same objective, which makes conjunctions unsound. Snapshot the ranges the pass needs, or halt the probe for the pass.

**Latching.** Unless `retractable` is true, an objective that reaches `complete` stays `complete`. `failed` always latches.

**Missing data is false.** A predicate over an absent channel, a path that does not exist, or a frame that failed CRC is **false**. It is never an error and never aborts the pass. A scenario that wants "the sensor is gone" says so with `channel_absent`.

## 8. Command Log Format

The command log is the save file. It is JSON Lines, appended one record per player uplink, and it is the sole persistence mechanism (charter R15.1).

```jsonl
{"seq":1,"t_ms":12480,"raw":"PEEK 0x2001E200 4","verb":"PEEK","charged":"reads","result":"ACK"}
{"seq":2,"t_ms":31002,"raw":"POKE 0x2001A1C4 43","verb":"POKE","charged":"writes","result":"ACK"}
{"seq":3,"t_ms":48110,"raw":"POKE 0x00000000 FF","verb":"POKE","charged":"writes","result":"NAK E04"}
```

| Field | Meaning |
|---|---|
| `seq` | Monotonic from 1. Gaps are a corrupt log. |
| `t_ms` | Probe uptime in milliseconds when the command was **applied**, not when it was typed. Replay uses this to re-apply at the same probe time. |
| `raw` | The exact uplink text, before delay and after checksum validation. |
| `verb` | First token, for filtering. |
| `charged` | `"writes"`, `"reads"`, or `null` for commands that cost nothing. |
| `result` | The probe's reply, verbatim. Recorded for evidence; replay does not depend on it. |

Rejected commands **are** logged. They cost budget, they are evidence for grading, and a log that silently dropped them would replay to a different budget state.

## 9. Replay and Revisions

**Replay.** Restoring a session means: start a fresh probe from the package's ROM, apply `setup.json`, then re-apply each logged command at its recorded `t_ms`, evaluating objectives at every frame boundary as if live. The resulting objective states **shall** equal those of the original session (charter R15.1, within 60 s for 500 commands).

This works only because of §6.6. It is the reason determinism is a requirement rather than a preference.

**Revisions.** A log records the `revision` it was produced under. Replaying a log against a **higher** revision is permitted and **shall** produce a warning, because changed assertions may legitimately reach a different verdict. Replaying against a different `id`, or against firmware with a different `app_crc32`, **shall** be refused.

## 10. Daemon Conformance Interface

To be testable without constraining its architecture, a daemon **shall** provide exactly one non-interactive entry point:

```
<daemon> conform --scenario <dir> --replay <log.jsonl> --out <state.json>
```

It replays the log per §9 and writes:

```json
{
  "format": 1,
  "scenario": "sojourn.comms.triage",
  "revision": 3,
  "frames": 24,
  "objectives": [
    { "id": "diagnose",  "state": "complete", "first_frame": 4 },
    { "id": "reprioritize", "state": "complete", "first_frame": 11 },
    { "id": "keep-budget", "state": "active", "first_frame": null }
  ],
  "budget": { "writes": 6, "reads": 22 }
}
```

The conformance suite (§11) supplies `(package, log, expected state)` triples and diffs this output. **Nothing else about the daemon is dictated** — not its language, its HTTP surface, its storage, or its console.

This is the whole acceptance gate for the format. A team that passes it has a daemon the sponsor can author against.

## 11. Reference Material Shipped With This Specification

| Artifact | Role |
|---|---|
| `scenarios/first-contact/` | Tutorial package. Three objectives, pure content, exercises telemetry and command-log predicates. |
| `scenarios/comms-triage/` | The Galileo bandwidth scenario. Four objectives across register, data and config patches; the intended acceptance target. |
| `firmware/tools/scenario_validate.py` | Static validator. Schema, symbol resolution, memory-map bounds, cycle detection, purity check (charter R13). |
| `firmware/tools/scenario_eval.py` | **Reference evaluator.** Drives a real probe, applies a log, evaluates this vocabulary, emits §10 output. Implements the §10 entry point itself, so the conformance runner drives it exactly as it drives a daemon. |
| `conformance/` | Fixtures — packages, logs, and expected state generated from real firmware runs — plus nine seeded-defect packages and `run_conformance.py`. |

Both reference packages are pure content and both currently pass. Run the whole gate against the reference implementation with:

```
python3 conformance/run_conformance.py --reference
```

which is 14 checks: 2 reference packages accepted, 9 seeded defects rejected each by its intended rule, and 3 replay fixtures agreeing objective for objective.

> **The vocabulary was changed by writing these.** `mem_bits` and `tlm_bits` (§6.2) do not appear in the first draft of this document. They were added because the comms-triage objective "the deployment drive was commanded and the dish still did not recover" could not be stated without them: the only alternative was to assert the entire value of a control register, which would break whenever an unrelated bit moved. The first version of that objective *did* pass — off the wrong event, before the player had done anything — which is exactly the failure a reference scenario exists to catch. Rule 4 of §6.7 is the general form of this lesson: when the vocabulary cannot say something ordinary, extend the vocabulary.

**On the reference evaluator.** It is an *oracle*, in the same sense `tools/tlm_decode.py` is the normative telemetry decoder: it exists to prove the vocabulary is sufficient and to generate expected outputs, and where this document and the evaluator disagree, one of them is a bug. It is **not** a starting point to extend into the daemon — it has no scenario discovery, no delay simulation, no persistence, no profiles, no console, and no HTTP surface, which is to say it does not do any of the things the daemon is for.

## 12. Validation Rules

`scenario_validate.py` **shall** reject a package for any of the following. The three classes named in charter R13 are marked.

| # | Rule |
|---|---|
| V1 | `manifest.json` absent, unparsable, or missing a required key **(R13: malformed manifest)** |
| V2 | `format` greater than the validator implements |
| V3 | A referenced file is absent |
| V4 | A predicate has an unknown `op`, a missing required key, or a malformed shape **(R13: unparsable assertion)** |
| V5 | An `at` reference names a symbol absent from `symbols.json` |
| V6 | A resolved address or range falls outside every `memmap.json` region **(R13: assertion address outside the memory map)** |
| V7 | `requires` names an unknown objective, or the dependency graph has a cycle |
| V8 | Duplicate objective `id` |
| V9 | A comparison's `value` type does not match its `op` |
| V10 | `checks/` present without `"impure": true`, or declared impure with no `checks/` |

Warnings, which do not fail validation: unknown manifest keys; an objective with no `hints`; a setup write with no `note`; a package declaring `impure`.
